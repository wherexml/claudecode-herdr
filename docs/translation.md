# 聊天翻译模式（本地扩展）

输入框下方开关控制本设备的聊天翻译。开启后，文字和已有语音输入转写结果在发送时翻译成英文；完成的 Agent 正文在进入可见范围后翻译成简体中文，可展开原文。原始 transcript、工具输出、审批选项、终端输入和 slash 命令保持原样。待发送队列保存原始输入，按“立即发送”时使用当前模式。

翻译服务在连接服务器上运行，配置只从后端环境读取：`HERDR_TRANSLATION_BASE_URL`、`HERDR_TRANSLATION_API_KEY`、`HERDR_TRANSLATION_MODEL`。本机 `.env` 被 Git 忽略，权限 0600；不要使用 `VITE_` 前缀。Go 的 base URL 是 `https://opencode.ai/zen/go/v1`，请求带真实客户端名称及稳定的会话标识，不伪装 OpenCode。

此接口是文本翻译；开启模式会显示聊天麦克风按钮，录音仍需主动点击。麦克风转写仍由现有浏览器语音识别或已有转写服务提供，不把文本模型当语音模型。浏览器识别语言跟随界面语言；多语言识别准确度取决于转写服务，不能保证任意口音都被正确识别。代码围栏、内联代码、URL、附件路径通过占位符保持原样。

## 修改前确定的失败场景与验收

- 缺配置、无权限、跨域、无效 JSON、空文本、过长文本、未知目标语言：明确拒绝，不返回密钥。
- 上游 401/429/5xx、超时、断流、空内容、截断输出、代码占位符丢失：不发送原文冒充译文，保留草稿；回复保留原文并提供重试。
- 翻译期间切换窗格、断线、关闭模式、出现审批或 Agent 开始工作：取消本次发送，保留原始草稿，不向错误窗格或菜单输入。
- 排队输入只在显式发送时翻译；失败不移除队列；命令不翻译。
- 回复仍在流式更新时不反复翻译；关闭模式恢复原文；翻译失败不破坏历史记录。
- 相同回复重复渲染不重复付费请求；缓存只在内存中且有容量限制。
- E2E：模式开关、原文/译文、失败保留草稿、窗格切换、终端回归；留存可重复步骤和结果。

上限：每次 24,000 字符，翻译最长 90 秒，同时最多 4 个请求；超过限制会提示重试。默认关闭，需要用户开启才会发送对话内容到配置的翻译服务。

## 可重复验收

1. 在项目目录使用 Bun 1.4+ 构建：`bun run build`。
2. 使用独立会话启动测试页面：`HERDR_TEST_SESSION=herdr-web-ui-test-translation bun scripts/translation-fixture.ts`。它监听 `127.0.0.1:17318`，两个测试窗格使用 cat 接收消息，不启动模型。窗格 ID 写入 `evidence/translation/fixture.json`。
3. 打开测试页，选择 Translation QA A → Chat，开启 Translation mode。输入“请检查项目，并保留 `npm run build` 命令。”并发送。切到终端确认英文文本到达且命令不变。
4. 关闭模式发送“原文直发 QA_MODE_OFF”，终端应收到中文。
5. 网络故障注入或临时拒绝 `/api/translation` 请求时，发送失败应保留草稿；在请求等待期间切换 B，A 的草稿应保留，B 不应收到任何文字。
6. 回复 UI 验证使用固定英文 transcript 测试夹具；真实翻译服务回译为中文，查看原文、失败重试、关闭模式恢复原文。夹具不是 Agent 生成回复的验收。
7. 结束测试时向 fixture 进程自身发送 SIGTERM，使其清理自己创建的工作区；不要结束用户的 Herdr 会话。

## 输入区提示与美西时钟

方向说明仅在悬停翻译开关或键盘聚焦时显示。右侧为小表情和“美西时间 HH:MM”；采用 America/Los_Angeles 时区，自动处理夏令时，每分钟及页面恢复可见时刷新。01:00–05:59 红色害怕脸；06:00–07:59、19:00–次日00:59 黄色皱眉脸；08:00–18:59 绿色微笑脸。此标记只显示时段，不阻止发送或改变 Agent 运行策略。

时钟验收：22 项夏令时/冬令时及 01、06、08、19 点边界检查通过（`evidence/translation/pacific-boundaries.json`）。浏览器检查默认隐藏、悬停显示、移出隐藏、键盘聚焦显示，以及时钟在开关右侧同一行（`evidence/translation/pacific-ui.json`）。重验：打开聊天，悬停/移出翻译模式，按 Tab 聚焦开关；用 America/Los_Angeles 的边界时间调用 `src/lib/pacificTime.ts` 对照上述表。

翻译工具栏与输入框共用 `--chat-w` 宽度和居中规则，取消工具栏额外左右内边距，确保翻译图标与输入框外边缘对齐（含窄屏与聊天宽度设置变化）。

## 翻译设置

设置弹窗在语音输入上方提供翻译开关、协议（OpenAI Chat Completions / Anthropic Messages）、API 基础 URL、API Key、模型 ID。读取 `/api/translation/settings` 只返回非敏感配置和 `has_key`；已有环境配置自动带入，密钥输入留空保留。更换地址必须重新提供密钥。POST 使用同源检查、现有访问角色限制和 `x-herdr-translation: 1`。保存立即生效，清理翻译缓存。

用户设置优先于环境变量，AES-256-GCM 加密保存到状态目录的 `translation.enc`，本机随机解密密钥 `translation.key`，两者权限 0600；目录 0700。不得将 API Key 回传浏览器或写入日志。重启保留设置；已有 `.env` 不改写。

OpenAI 基础 URL 应包含服务商要求的路径（例如 `/v1`）；Anthropic 自动补充 `/v1/messages`。两种协议都拒绝截断输出并保留代码路径保护。协议参考：https://platform.claude.com/docs/en/api/messages/create 。

验收覆盖：配置自动带入、留空保留密钥、保存/刷新持久化、协议切换、无权限/跨源拒绝、URL 改变要求新密钥、OpenAI 和 Anthropic HTTP 请求与返回、磁盘密文不包含 API Key。真实 Anthropic 服务需用户提供对应账户；本次用隔离 HTTP fixture 验证协议。

聊天历史浏览器夹具为 `/api/translation` 提供未配置响应，使真实 Composer 在隔离环境中不会将新 API 路径误当静态文件读取。
